# Puipuiの操作と読みやすさ

Puipuiを久しぶりに開いても、状態と操作の結果を理解できるようにする。設計インタビューとFigmaレビューの合意に基づき、A案を実装する。

## 合意済み

- 主な利用者は、ターミナルを利用できる開発者本人。Moleの状態やコマンドの意味を覚えていることには頼らない。
- Puipuiは状態確認と組み込みターミナルを提供する。整理コマンドの入力と削除開始はユーザーが行う。
- 容量確認、スキャン、整理の実行準備の流れを改善する。
- 余白の冗長さと文字の小ささも今回扱う。読みやすさと情報密度を一緒に検討する。
- メニューバーから開いて数秒で確認する使い方を基準にする。独立表示でも同じ情報配置を使う。
- 現在の320pt幅には固執しない。不要な余白を減らし、読みやすさのために必要なら幅を広げる。寸法は画面案で比較する。
- 明るい計測エリアと暗い操作エリアの配色は残す。数値には等幅の数字、説明と操作名には読みやすい通常の書体を使い、全大文字にはこだわらない。
- 情報の強弱（Q5）はFigmaのA案を採用する。幅320ptで数値とグラフを行ごとに配置する。
- Puipuiはmoコマンドのラッパーとして使う。組み込みターミナルは、その場で素早く確認・操作するための中心的な機能。
- 表示言語を日本語にすることは合意していない。ミニマルなUIを志向し、ラベルや状態説明の表現もFigmaで議論する。
- 起動時にバックグラウンドでスキャンする。その後は直近のスキャン完了から1時間後に再実行し、手動スキャンも起算点を更新する。パネルを開くたびには実行しない。
- CLEAN操作は削除する。ターミナルはスキャン結果やMoleの利用可否にかかわらず開ける。スキャン失敗とMole自体が利用できない状態は区別する。
- 再スキャンに失敗しても前回の成功値と計測時刻を残し、更新失敗を区別する。一度も成功していなければ未取得とする。
- スキャン中はScanの再操作を止める。通常のターミナルは開けるままにし、本人が入力するコマンドは制限しない。
- Moleの自動インストール・自動更新はしない。利用不可の理由と対処方法を詳細から確認でき、環境を直した後に再確認できるようにする。通常表示はミニマルに保つ。
- ログインシェルのPATHからmoの実行ファイルを探す。独自のエイリアスやシェル関数は今回対象外。検出した場所と対応状況を詳細で確認できるようにする。
- ターミナル内のコマンド完了監視は追加しない。整理後の再集計は手動SCANか定期スキャンに任せる。空き容量は通常どおり更新し、整理可能な容量には計測時刻を付ける。ターミナルを閉じたことを整理完了とは扱わない。

## 最終の画面構成

- 重複するPuipui / Last 5 min見出しと、読み取りにくい空き容量バーを削除する。
- CPUとMemoryを面グラフにする。CPUはUser（niceを含む）とSystemを色分けして積み上げる。Memoryのグラフは使用率で、PressureのラベルはOS通知の状態を示す。
- NetworkはRXを上、TXを下にし、両方向に共通のスケールを使う。上下限・中央線・5m ago / nowを表示する。未取得区間や計測が途切れた区間は空白とする。
- 常設操作はTerminalと三点リーダーだけにする。ScanとQuit Puipuiは三点メニューに配置する。
- 情報アイコンは最終成功・次回予定・Moleの状態とパスを表示する。矢印のない角丸と影のポップオーバーをアイコンの上に重ね、背景を暗くしない。外側クリックかEscで閉じる。
- 表示は短い英語ラベル。FigmaのInter代替に対し、アプリはネイティブのシステムフォントを使う。

## 次の工程

合意したA案を実装し、文字サイズ・余白・ポップオーバーとメニューの動作、独立ウィンドウ、ターミナルを実機で確認する。

用語と合意事項は決定ごとに更新する。画面案は設計判断を踏まえて作り、選択後に実装へ進む。

[Puipui / Design review](https://www.figma.com/design/spwA1eEgycGIK1TtjHZ45R/puipui?node-id=5-33)に現状再構成と3案、操作状態、参照部品を作成した。A案を採用し、[情報ポップオーバー](https://www.figma.com/design/spwA1eEgycGIK1TtjHZ45R/puipui?node-id=15-198)の矢印削除まで合意した。

- A: 幅320ptで縦並びを維持。文字を大きくする分、高さは増える。
- B: 幅360ptで数値と波形を行ごとに配置。
- C: 幅400ptで3指標を横並びにし、高さを抑える。

Base UIのButton・Popover・Tooltip・Progressを編集可能な参照部品として再構成し、出典とPuipuiでの用途を添えた。直接のWebページ取り込みではない。Lucideは公式SVGを利用。Emil Kowalskiのemil-design-engとapple-designを参照した。

Figma実行環境ではSF Proの文字が正常描画されなかったため、比較案はInter、現状の等幅部分はRoboto Monoで代替している。実機と同一の書体・ピクセル再現ではない。Figmaの開閉動作は注記で表現している。

## 実装と検証（2026-10-15）

`design-discussion` worktreeに実装。通常表示は320×420ptで、独立表示だけ上部に32ptを加える。Scanの失敗表示が増えても下部操作が切れないよう、状態欄には2行分を確保した。

- Swift Testing 6件成功。CPU内訳と未取得・カウンター巻き戻り、PATH順序、起動時スキャン、二重実行防止、失敗時の前回成功値保持、手動実行による次回予定更新、Mole互換性の再確認、既存のプレビュー検証を確認。
- 署名付きreleaseビルドとcodesignのstrict検証成功。
- `--check-metrics`成功。実機のCPU・メモリ・ネットワークを取得。
- `--check-window --render-window`成功。ポップオーバーでサイズが変わらずEscで閉じること、ドラッグ・独立表示・閉じる・再表示を確認。
- 実操作で情報アイコン、外側クリック、Esc、三点メニューのScan、次回予定更新、Terminalの開閉、Quitを確認。
- `--check-terminal`で接続・入力・回収・同梱リソース・シェル設定・再表示を確認。展開途中の幅を60ms後に1回だけ観測する既存判定は不安定で、変更前のmainでも失敗し、今回の最終診断実行では全項目成功した。アニメーション自体の実装は変更していない。

Mole 1.53.xと1.59.xに対応する。1.59系の`counted under`付き候補は親に含まれるため加算しない。未集計の`size unknown`は不完全な結果として拒否する。2026-10-15に実機の1.59.1で`--check-scan`が成功し、1,969,762,000 bytesを集計した。対応版・非対応版の実行制御、重複候補の集計、従来の状態遷移を含むSwift Testing 9件が通過した。
